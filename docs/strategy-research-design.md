# 戦略リサーチ設計サマリ (USDJPY マルチタイムフレーム)

> このドキュメントは Claude Code に渡すための設計合意書。実装はこの方針に従う。
> コードを書く前に、まずこのファイルを読んで文脈に乗ること。

---

## 0. 目的

複数の自作 Pine スクリプト(指標)を題材に、再現性のある売買方式を見つける。
単一戦略のチューニングではなく、**指標の状況・位置関係**から良好パターンを探すのが主眼。
手作業のバックテストが膨大で疲弊したため、機械的・反復的に回せる仕組みを作る。

---

## 1. 二つの分析軸

性質が逆な二つの探索を**両方**回す。

### 軸1: アウトカム起点(発見)
- 「実際に大きく上昇/下落した」局面を起点に、**その手前で各指標がどんな状況だったか**を遡って調べる。
- 目的: 自分が思いつかなかった指標の状況パターン → **新しい方式の種**を拾う。
- 主敵: ベースレート無視、稀少イベントによるサンプル枯れ。

### 軸2: シグナル起点(活用)
- 既存スクリプトのシグナル/パラメータを起点に、**組み合わせで良好パターン**を探す。
- 目的: 現行最適パターンでの運用。
- 主敵: 多重検定(試行数の爆発による偶然の勝者)。

### 合流の扱い(重要)
- 二値(採用/不採用)にしない。**信頼度ティア**で表現する。
  - **Tier A**: 両軸で出た + 複数足で再現 → 確度高・配分大。
  - **Tier B**: 片軸のみ、ただし検証データで生存 → 採用・配分控えめ。
  - **Tier C**: 片軸かつ検証が弱い → 保留(消さずに見せる)。
- 「両方必須」で弾くと機会が激減するので**しない**。状況を見て配分で判断。
- 合流は多数決でなく**独立確認**として使う(別期間/別足で当てる)。

---

## 2. 対象と単位

- **銘柄**: USDJPY
- **エントリー足**: 1分足(M1)。判断とラベルの主体は M1。
- **上位足(文脈フィルタ)**: M15 / H1 / H4 / D / W。エントリーはせず、M1 の判断に文脈を与える変数。
- **分析単位**: 1行 = 1イベント(トレード or シグナル発生)。列 = 結果 + エントリー時点のコンテキスト特徴量。

---

## 3. 法則の不変性という前提(本プロジェクトの肝)

- **同じ法則を六足すべてに適用**する。形は共通、**パラメータの影響度(係数)だけ足ごとに可変**。
  - 下位足ほどテクニカル的・高ボラ、上位足ほどニュース駆動・低ボラ。
- これにより「1スケールで大量サンプル」ではなく **「複数スケールで法則の不変性を確認」** を検証の主役にする。
- 週足のサンプルが少ないのは欠点ではない。**6足を独立した検証集合**として扱える。
  - スケールをまたいで生き残る法則 = レジーム非依存の本物、という強い証拠。
- → サンプルを数年分盛る必要はない。**むしろサンプルを減らす(厳しくしすぎる)方がリスク**。

---

## 4. 特徴量方針

- 全特徴量を **ATR 正規化**(生 pips でなく「ATR 何本ぶん」)。これでボラ差を自動吸収し、足を跨いで同じ土俵に乗る。
- 各指標を**所属足ラベル付き**で持つ。命名規則:
  - `W_*` `D_*` `H4_*` `H1_*` `M15_*` `M1_*`
  - 例: `W_trend_dir`, `H4_gapAB_atr`, `M1_velSlope`
- 位置関係の数値化: 順序(状態カテゴリ)、ギャップ(ATR正規化)、傾き、価格位置、収束/拡散、クロス後経過本数。
- **足間整合性特徴量**(役割分担の核):
  - `align_score`: 六足のうち同方向の本数(0〜6)
  - 上位/下位の合致フラグ(例: W・D・H4が上 かつ M1が押し目)
  - 不一致フラグ(上位足と下位足が逆 = だましの温床)
- **次元の呪い対策**: 最初から全部入れない。整合性特徴量 + 核スクリプトの主指標だけで開始し、効いたものだけ足す。

---

## 5. 結果指標

- **R倍率(R-multiple)で評価**。R = 損切りまでの距離(リスク)。+2R = リスクの2倍取れた。−1R = 損切り。
- 勝率単体は使わない。判定は**期待値** = 勝率 × 平均勝ちR − (1−勝率) × 平均負けR。
- **1R = ATR(14) × 1.5**(固定 pips でなくボラ追従)。利確は複数試行(1R / 2R / 3R / トレーリング)。
- **「大move」定義(軸1)**: 今後 H 本以内に始値から閾値 ATR 超の動き。上/下でラベル。

---

## 6. 過学習対策

サンプルを盛らない方針なので、**主役は期間分割より足横断**。

- **足横断再現**: ある足で発見 → 別の足で再現するか(クロス足バリデーション)。採用基準は「6足中5足で同方向に効く」。
- **足内時系列分割**: 各足で前半発見・後半検証。検証データに特徴量選択を触らせない。
- **walk-forward**: 時間をずらして学習→未来検証を反復。
- **最低サンプル数の足切り**: n が小さいセル/葉は信用しない(例 n<10 は参考表示のみ)。
- **多重検定の意識**: 100通り試せば数通りは偶然 p<0.05。発見はすべて**仮説**として再検証。
- **ナイフエッジ回避**: 尖った最大値より、少しずらしても緩やかに保たれる関係を採る。
- 探索の格子(複数版で幅を見る、過学習除けそのもの):
  - 大move判定期間 H: 15 / 20 / 30 / 60 本
  - 閾値: 1.0 / 1.5 / 2.0 ATR
  - R設定(利確): 1R / 2R / 3R / トレーリング

---

## 7. 結果が必ず見える原則 (no-empty-result) ★最重要の歯止め

厳密な足切りで「該当なし」しか出ないと判断材料がゼロになる。これを禁止する。

- **出力層に二値(採用/不採用)を持たせない**。出力は常に「順位付きの全景 + 確度ラベル」。
- **フィルタ型でなくスコア型を土台に**する。基準未達も**グレー表示で残す**。
- **常にフルランキングを出す**: 全パターンを 期待値・勝率・取引回数・足横断スコア の列付きで一覧。
- **比較基準線を必ず併記**: 各パターンを「平時のベースレート」「無条件の期待値」と並べる。
  最強パターンが基準割れでも、それが分かること自体が結果。
- **緩い閾値から始める**: 最初は緩く回してサンプルと結果を確保 → 後で締める。逆順は禁止。
- 採否はユーザーが景色を見て決める。**判断を奪わない**。

## 10. 最初のタスク粒度(小さく始める)

1. 核スクリプト1本(下記 Physics Matrix)の指標を Python に翻訳。
2. M1 で特徴量化(ATR正規化)。
3. 軸1: 大move ラベル + ラベル別の指標分布 + lift テーブル + 浅い決定木。
4. **no-empty-result でフルランキングが出ることを確認**。
5. 動いたら → 六足展開 → 軸2(組み合わせ) → Tier 合流、の順で拡張。

## 付録A: 初回題材スクリプト「Physics Matrix」(v63.5+F) の特徴量化メモ

価格の高次微分を正規化した物理モデル。研究対象の「ラインの位置関係」がそのまま指標になっている。

- **計算系列**:
  - `src_smooth = HMA(close, 6)`、`mid_line = HMA(src_smooth, 72)`
  - `raw_vel = mid_line - mid_line[1]`(1次微分)、以降 `acc`(2次)、`jerk`(3次)、`snap`(4次)は差分の差分。
  - 各々を `f_norm(x) = x / stdev(x, 100)` で正規化 → `n_vel, n_acc, n_jerk, n_snap`。
- **特徴量候補(各足で生成)**:
  - 4層それぞれの: 値、傾き(`>[1]`=上昇)、極性(`>0`=正)。
  - 階層関係: `n_acc vs n_vel`, `n_jerk vs n_acc`, `n_snap vs n_jerk`(どちらが上か)。← 位置関係の核
  - `n_vel` の強度(force閾値 2.0 との比較 = パニック領域か)。
- **補助フィルタ(スクリプト内蔵、特徴量化候補)**:
  - トレンドマスク(elastic system のバンド状態 = bull/bear)。
  - MAフィルタ(HMA72 と SMA72 の方向一致)。
  - Vel デッドゾーン(`|n_vel| < 閾値` = 弱い)。
- **注意**: `calc_on_every_tick=true` だが研究では足確定ベースで計算(リーク回避)。
  正規化は過去 100 本の stdev なので、各時点で過去データのみから計算可能(リークなし)。
